# 新規草花登録・画像追加スキル (add-new-plant)

ユーザーが「草花登録して」や「〇〇を登録して」などと発言した場合、以下の手順に沿って手続きを進めるニダ。このスキルは必ず**日本語**で、かつ語尾に「**ニダ**」をつけて対応するニダ。

## 手順1: 草花名の確認
追加したい草花の名前（和名。例: 「アダン」）を確認するニダ。
もし既にユーザーの発言に「〇〇を登録して」と書かれている場合は、その名前を使用するニダ。そうでない場合は、ユーザーに「どの草花を登録するニダ？」と尋ねるニダ。

## 手順2: 補助スクリプトの実行
草花名（和名）が特定できたら、`run_command` を使用して、このローカルスキルに内包されている自動登録スクリプトを実行するニダ。

**実行コマンド例:**
```bash
node .agents/skills/add-new-plant/scripts/register_plant.cjs "草花名"
```
（Cwd は `C:\Gravity\amamikusabana_2` とするニダ）

## 手順3: 実行結果の確認とエラー処理
コマンドの実行結果（標準出力・標準エラー出力）を確認し、ユーザーに報告するニダ。

- **成功した場合**:
  - バックアップが作成され、JSONが正常に更新されたことを伝えるニダ。
  - リネームされた Markdown ファイルが `C:\Gravity\KUSABANA_SEIRI\motomemo_md` フォルダへ移動されるニダ。
  - もし移動先に同名の Markdown ファイルが既に存在する場合、移動は行われず「`mdがすでにあったのでmotomemo_mdには追加できませんニダ`」という警告が出るニダ。
- **一部の画像が移動先に重複していた場合**:
  - スクリプトから「`id_nn.jpg`は既存しています。調べてから自分でimagesフォルダに移動してくださいニダ。」という旨の警告が出力されるニダ。その警告文をそのままユーザーに表示して注意を促すニダ。
- **エラーが発生した場合**:
  - スクリプトが出力したエラー（例：「その草花mdは既にあるので新規登録できません」「〇〇を含むMarkdownファイルが見つかりません」など）をそのままユーザーに伝え、処理を中断するニダ。

## 手順4: JSON編集画面の起動（最終確認）
スクリプトが正常終了（または画像重複警告のみで終了）したら、ユーザーに「登録が終わりました。最終確認してくださいニダ。」と伝えるニダ。
その後、`run_command` を使用して、以下のバッチファイルを実行するニダ。

**実行コマンド:**
```powershell
C:\Gravity\KUSABANA_SEIRI\JSON_EDIT\run_server.bat
```
（Cwd は `C:\Gravity\KUSABANA_SEIRI\JSON_EDIT` とするニダ。WaitMsBeforeAsync は 500ms 程度にし、サーバープロセスをバックアップに回すニダ）

バッチファイルを起動して、ブラウザで編集画面が開かれる状態になったら、処理完了ニダ！
